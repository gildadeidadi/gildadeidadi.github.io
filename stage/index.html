2 Crea struttura fogli

Verrà eseguita la funzione setupFogliConfig() che crea i fogli necessari solo se non esistono già. Dopo il setup vengono applicate automaticamente le migrazioni (aggiunta colonne, allineamento dati) anche sui fogli già esistenti. È un'operazione sicura e idempotente.

⬜ Foglio Config (chiave / valore / descrizione)
⬜ Foglio Eventi (eventId / nome / data / luogo / indirizzoLuogo / descrizione / attivo)
⬜ Foglio Sessioni (eventId / sessioneId / nome / orario / attivo / maxPosti / tipoSessione / fasciaEtaMinima / giochiDisponibili)
⬜ Foglio Tavoli (eventId / sessioneId / id / gioco / tipo / max / occupati / fasce / partecipanti / attivo / sistemaGioco / titoloAvventura / descrizione / fasciaEtaMinima / master / mostraMaster / descrizioneTavolo)
⬜ Foglio Avventure (avventuraId / masterId / masterNick / titoloAvventura / sistemaGioco / livello / tipo / max / occupati / descrizione / tema / ambientazione / fasciaEtaMinima / mostraMaster / attivo / createdAt / updatedAt / tono / tematicheSensibili)
⬜ Foglio AvventureTavoli (linkId / avventuraId / tavoloId / createdAt – FK verso tavolo; evento/sessione solo sul foglio Tavoli)
⬜ Foglio FasceEta (fasciaId / fascia / ordine / attivo / note)
⬜ Foglio SistemiGioco (sistema / attivo / ordine / note)
⬜ Foglio Luoghi (nomeLuogo / indirizzo / attivo / createdAt / updatedAt / note)
⬜ Foglio Utenti (uuid / email / nome / cellulare / primaPrenotazione / ultimaPrenotazione / totPrenotazioni / eventiDiversi / note)
⬜ Foglio AvvisiEventi (storico invii evento/utente – avvisoId / eventId / uuid / email / nome / destinatarioTipo / stato / sentAt / errore / note)
⬜ Foglio Masters (masterId / nome / nick / email / cellulare / primaAssegnazione / ultimaAssegnazione / totTavoli / eventiDiversi / sessioniDiverse / note)
⬜ Foglio Partecipanti (co-prenotanti / inviti – participantId / bookingId / eventId / sessioneId / ownerUuid / participantUuid / nome / email / statoInvito / ruolo / inviteToken / tokenScadenzaIso / createdAt / updatedAt / nomeCompleto)
⬜ Foglio Amicizie (rubrica utente – friendId / ownerUuid / nome / email / cellulare / note / createdAt / updatedAt / stato)
⬜ Foglio Migrazioni (id / descrizione / data_esecuzione – log migrazioni schema)
⬜ Foglio _ESEMPIO nel file Risposte (intestazioni)

Migrazioni: aggiornano fogli già esistenti (es. aggiunta colonna Stato in Risposte, spostamento dati). Eseguile dopo un aggiornamento dell'app se hai fogli creati con versioni precedenti.

3 Genera hash password organizzatore

Genera l'hash SHA-256 della tua password. Verrà salvato automaticamente nel foglio Config alla chiave org_password_hash.

Clicca Salva nel foglio Config per scrivere l'hash alla chiave org_password_hash. Da quel momento la nuova password sarà attiva immediatamente, senza toccare il codice.

↓
4 Test email

Invia email di prova all'indirizzo configurato in EMAIL_TEST_NOTIFICHE (oppure agli organizzatori se vuoto), per verificare i template.

✅ ultima prova: —

I contenuti saranno marcati come [TEST] e non influenzano i dati reali.

5 Opzioni avanzate

Qui puoi abilitare il comportamento avanzato della lista d'attesa. Se disattivato (default), quando si libera un posto viene scelto il primo iscritto che ha quel tavolo tra le preferenze, in ordine cronologico.

↓
6 Trigger schedulati

Configura e controlla i job automatici. Coda email ogni 30 minuti; backup fogli Config/Risposte ogni giorno alle 3:00 (cartella Drive Gilda Prenotazioni - Backup, retention configurabile con BACKUP_KEEP).

Stato trigger non ancora caricato.
Stato backup non ancora caricato.
